## 已实现的行为

- 战前离线计算，不自动施法；进入战斗取消当前求解，战斗中不能开始计算或应用。
- 使用当前选中 Raidary Plan 的草稿，不读取另一份自动绑定方案。切一级标签不改变输入版本，也不取消任务。
- 手动填写结束时间；固定喷喷球 / 允许替代组合。先满足硬约束，再按总球、总喷、BBY 波数、BYB 波数、球更早、喷更晚、释放更晚比较。
- 只有完整搜索完成且独立验证通过才显示“模型内最优”。预算内的可行解与尚未证明最优明确区分。
- 结果显示完整手动施法时间轴、每波存好/释放时间、球/喷手动和复制次数、满充能空转与减冷却溢出明细。复制技能不额外写施法行。
- 计算不改原文、不切来源、不启用。应用前重新核验方案 ID、草稿内容/版本、参数版本、本人身份和别名解释；再次重放验证后只 SetDraft。
- 应用保留原文每个字节（包括回溯、他人安排、注释），追加生成的手动技能，原静滞行不重复。原文仍精确等于最近一次生成结果时从 baseText 重算；手改过的生成技能不被自动删除。输入中有本人手写喷/球/花/释放时明确拒绝并提示整理。
- 可选元数据放在原方案的 dreamLoom 字段，包含参数和生成来源；没有新增方案库。
- 球的读条按实际 START 与同一可读 castGUID/castBarID 的 SUCCEEDED 确认，不用 2 秒计时器判成功。匹配时选择原窗口内最近计划事件。身份冲突/不可核实时不确认；不会消耗绿喷 token 或推进静滞波次。
- 0.9 秒设置保持不变；仅已匹配起手的球暂留，15 秒为丢失回报的清理上限，不代表成功。STOP 本身不判成功或失败。失败后在原窗口内允许重试，超出窗口则按错过处理。
- 球、花目前无专用音频文件，因此只提供视觉提醒，不注册虚构音频，也不借用绿喷紧急语音。花已支持解析/到点提醒，未把无法区分手动与复制的花成功回报接成自动确认。

## 2026-09-28 第一阶段审计修复与 COMPLETE 证据

修复四个问题：不完整绿喷配额误判、漏读球安排后误提示取消、CRLF 保存后无法重生成、复制/恢复历史丢失生成来源。

### COMPLETE 的边界

COMPLETE 表示“当前读取的原文在已支持语法和当前本人身份下有全量覆盖证据”，不是对用户意图或现实全部安排的保证。它不能证明用户没有写错角色名、没有在插件外另写安排，也不能证明尚未支持的任意自然语言已被理解。

必须同时满足：

1. **输入覆盖**：MRT 已确认所选原始文本字段均可读（字段缺省按 MRT 空文本语义处理）；Raidary 读取当前解析目标的完整保存文本。结构化来源不能仅凭转换结果解析成功获得此证明。
2. **逐行、逐分段覆盖**：每一段要么是完整解析的本人安排，要么有明确的单一目标、完整技能载荷，且由可读团队/小队单位身份确认是非本人。仅名字不匹配，不算他人安排的证据。
3. **可忽略内容有显式语法**：空行；无可解析时间的 `#`、`--`、`//` 注释。普通标题、自由文字、缺失时间、无法解释的尾段不会自动忽略，记 UNKNOWN。
4. **没有已知缺损/冲突**：已知技能安排解析失败、相对阶段时间不支持、别名冲突、结构问题、来源报错等记 PARTIAL 或禁止纠错。

`result.integrity` 记录 state、scope、行号、行状态、分段判定和覆盖计数；诊断日志保存副本。UNKNOWN 和 PARTIAL 均不允许 negativeCorrectionAllowed。没有证据对象、没有显式 true 的战斗快照同样禁止负向纠错。

目前 NSRT / DFT 适配器不能证明所有原始节点均已处理，因此即使转换文本全都解析成功，整体仍为 UNKNOWN。保留正常提醒与可靠成功确认，暂停负向纠错；不是将其已有功能判为失效。后续只有补齐原始节点的覆盖证据后才可放行。MRT / Raidary 含普通未解释文字或未核实目标时，也会保守暂停纠错。概览页显示暂停状态及检查结果中的未覆盖行号。

### 执行边界

- PlanGuard、战斗快照、绿喷配额判断/提前迟到判断、球起手取消判断共享完整性许可。
- UNKNOWN/PARTIAL 不发“取消蓄力”“先别喷”“绿喷晚了”“取消读条”“溜溜球晚了”等负向判断。
- 已解析内容继续到点提醒；球在正常提醒窗口内起手仍可关联同次成功，读条中保留提示。真实绿喷施法仍记录。
- 不更改当前战斗快照。编辑原稿变完整，不会在本场中途把旧快照升级为允许纠错。
- 空战术板保持中性，不新增完整性警告。

### 生成来源修复

换行仅做 CRLF/CR→LF 的等价比较和保存规范化，不忽略其他内容变化。复制方案深拷贝参数和来源；来源记录与当前保存正文、最近十次正文历史配套保留。恢复历史只恢复草稿与对应生成来源，仍由用户保存/启用；原 history 保持字符串数组。手改生成技能不会被静默删除。

旧版本已经丢失来源的历史正文无法凭内容可靠反推来源；此类记录继续拒绝自动删除/替换本人手写技能，不猜测元数据。

## 2026-09-28：完整性按技能域与已知计划项拆分

本节覆盖上一阶段“所有负向提示统一要求 COMPLETE”的描述。

### 判断边界

- `integrity.domains[skillKey]` 保存技能域的 COMPLETE / UNKNOWN / PARTIAL 及候选行号、绝对时间。`absenceAllowed` 是各域的缺少安排判断权限；旧 `negativeCorrectionAllowed` 仅保留诊断汇总，不再控制战斗提醒。
- COMPLETE 的证据是：遍历当前输入，按支持语法将候选段登记为本人已解析、已证实其他队员、或不确定候选；本域没有未覆盖候选。实际来源还必须提供原始输入完整覆盖证据。没有证据对象不会取得纠错权限。
- 普通说明（包括编号说明）不要求理解其自然语言含义。没有时间/玩家/法术安排标记的说明标为 NOTE；显式注释标为 COMMENT。本人选择器、时间标记、法术标记、裸支持技能等仍作为疑似安排检查。技能未知则保守影响所有可能技能域，不能猜成无关文字。
- 已证实其他队员的显式归属可以排除，即使其技能或时间损坏；混合多人段仍分别核验。无法取得可读队伍身份时，不凭名字长相判定为他人。
- 球完整性按本人球技能域。绿喷配额还依赖静滞/释放边界：有绝对时间的异常限制到相关波次；无法解析阶段时间时只保守限制相关技能域，暂不宣称该阶段已被可靠定位。

### 两类语义

- absence-based：取消读条、取消蓄力、绿喷超额、先别喷。球需要 BALL 域许可；绿喷需要该波正向覆盖证据及可靠运行时配额/波次对位。UNKNOWN/PARTIAL 范围不能作不存在性推断。
- known-slot：球到点、施法中、球晚了、明确绿喷计划项到点/迟到。来自可靠本人解析项，不受无关域不完整影响。球继续 START 绑定槽位、匹配 SUCCEEDED 核销，STOP 不代替成功。
- 无配额的可靠绿喷项增加独立确认路径：只有唯一可关联的已知项才与起手绑定；匹配的蓄力结束且 complete=true 才核销。多个候选时不猜。该路径不借用下一波、不修改配额账本。

### 来源限制

NSRT / DFT 仍缺少原始节点完整覆盖证明，因此不能启用球取消读条或绿喷配额、提前、取消蓄力等不存在性判断。规范化后可靠解析的本人项可以到点/迟到显示及接受匹配施法确认。未支持的阶段格式仍不生成安排；未知技能、未知身份不会获得可靠 slot 标记。

### 文件与验证

- Parser.lua、PlanGuard.lua、PlanSources.lua：候选分类、技能域证据、波次限制和来源覆盖门槛。
